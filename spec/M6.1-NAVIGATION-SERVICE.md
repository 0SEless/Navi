# M6.1 — Navigation Service

## What

Create a `NavigationService` capability on `RuntimeEngine` that provides route-finding, nearest-node/entrance lookup, reachability checks, and route summaries — without exposing `RoutingEngine` or `AStar` to application code.

Currently `RuntimeEngine` exposes `engine.routing.findRoute()`. The goal is to replace `routing` with a richer `navigation` service that encapsulates A*, graph queries, entrance resolution, and route summarization behind a stable, product-oriented API.

**Invariant:** NavigationService is a read-only consumer of `LoadedPackage`. It never mutates package state.

## Success Criteria

1. `RuntimeEngine` exposes `engine.navigation` with: `findRoute`, `nearestNode`, `nearestEntrance`, `travelTime`, `isReachable`
2. `findRoute` reuses the existing A* pathfinding — no new routing algorithm
3. `nearestNode` returns a domain result (`{ nodeId, distance }`) — never exposes `NavNode`
4. `nearestEntrance` returns the nearest entrance node to a given position — entrance identification is an implementation detail
5. `travelTime` returns `{ seconds, minutes, formatted }` computed from a `Route`
6. `isReachable(a, b)` returns `true`/`false` — thin wrapper around `findRoute`
7. Route now carries `travelTime` as a computed property so applications don't call a separate service for it
8. `RoutingEngine`, `AStar`, `RoutingAPI` exports remain for backward compatibility — but `RuntimeEngine` no longer exposes them publicly
9. All existing tests pass; new tests cover all methods and edge cases

## Non-goals

- No changes to AStar, RoutingEngine, or underlying graph types
- No multi-floor orchestration (future capability)
- No accessibility-aware routing (future capability)
- No changes to the compiler, publisher, or loader
- `RoutingAPI` class may be removed from `RuntimeEngine` constructor but remains importable

## Acceptance Criteria

- `engine.navigation.findRoute("A", "B")` returns same `Route` as current `engine.routing.findRoute("A", "B")`
- `engine.navigation.nearestNode({lat, lng})` returns `{ nodeId, distance }` with distance in meters
- `engine.navigation.nearestEntrance({lat, lng})` returns nearest entrance node result
- `engine.navigation.isReachable("A", "B")` returns true for connected nodes, false for nonexistent IDs
- `route.travelTime` is a computed property: `{ seconds, minutes, formatted }`
- All methods handle edge cases: null route, nonexistent node, empty graph

## Technical Considerations

- `NavigationService` wraps `RoutingEngine` — does not reimplement A*
- Nearest-node search is O(n) over graph nodes; fine for campus-scale graphs under 50k nodes
- Follows ADR-013 Capability pattern: initialized from `LoadedPackage`, single responsibility, no persistence
- `RuntimeEngine` constructs `NavigationService` in its constructor, replacing current `RoutingAPI` creation
- Route carries `travelTime` as a computed getter — no lazy generation needed since instructions are already computed during routing

## Known Pitfalls

- Don't delete `RoutingEngine` or `AStar` — other tests and downstream code import them directly
- `DataAPI`, `SearchAPI`, `PositionAPI` patterns serve as reference for the service structure but are not required to change
- Walking speed constant (1.4 m/s) must remain consistent between `RoutingEngine` and the new travelTime computation
