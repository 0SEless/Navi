# M3.2.2 Phase 4.5 — Editing Engine

## What

Define how editing actually works in the Interior Editor. This replaces the earlier "Interior Interaction Model" spec with a broader architecture that encompasses interaction rules, the editing lifecycle, geometry operations, selection, dirty state, and validation.

"User" always means the campus administrator editing indoor spaces. End-user navigation behavior is out of scope.

---

## 1. Editing States

The Interior Editor is always in exactly one interaction state:

```
                 ┌─────────────┐
                 │    Idle     │
                 └──────┬──────┘
                        │
            ┌───────────┼───────────┐
            ▼           ▼           ▼
     ┌──────────┐ ┌──────────┐ ┌──────────┐
     │ Drawing  │ │ Selecting│ │ Panning  │
     └──────────┘ └──────────┘ └──────────┘
                          │
                          ▼
                   ┌──────────────┐
                   │Editing Vertex│
                   └──────────────┘
                          │
                          ▼
                   ┌──────────────┐
                   │   Moving     │
                   └──────────────┘
```

| State | Entered by | Exited by | Description |
|-------|-----------|-----------|-------------|
| **Idle** | App start, tool deactivation, cancel | Tool activation | Nothing in progress. Canvas navigable. Selection may exist. |
| **Drawing** | Activating Room/Hallway tool | Confirm, Cancel, Escape, tool switch | Accumulating polygon points on click. |
| **Selecting** | Click on entity in Select tool | Click on empty space, Escape, tool switch | Single-click selects entity under cursor. |
| **Editing Vertex** | Double-click selected polygon entity | Confirm (click away), Escape, tool switch | Vertex handles visible. Click + drag handle to move it. |
| **Moving** | Drag selected entity body (not vertex) | Mouse up, Escape | Entity translates with pointer. Dispatches geometry operation on mouse-up. |
| **Panning** | Space held, Middle-click, Scroll-wheel | Space released, Middle-click up | Temporary modifier — tool state is suspended, not lost. |

### Exclusivity rules

- Exactly one state at all times
- Panning is a **temporary modifier** — holding Space suspends the current state and returns to it on release
- Vertex Editing cancels Drawing
- Idle with selection is allowed (selection persists across Idle)

---

## 2. Interaction Rules (Invariants)

These are invariants enforced by the state machine, not suggestions for UI components.

| Rule | Enforcement |
|------|------------|
| Only one active tool at a time | ToolRegistry rejects activation if another tool is active |
| Only one editing state at a time | State machine enforces mutual exclusion |
| Drawing cannot occur during Move | State machine prevents transition |
| Vertex Editing cancels Drawing | State machine transition rule |
| Selection persists while changing tools | SelectionManager is independent of ToolRegistry |
| Space overrides everything with Pan | Input handler intercepts before tool handler |
| Escape does three steps: cancel drawing → clear selection → noop | State machine processes escape in priority order |

## 3. Editing Lifecycle

Every edit follows exactly the same lifecycle:

```
Start
  │
  ▼
Preview     ← visual feedback only
  │
  ▼
Validate    ← editing validation (cheap)
  │
  ▼
Commit      ← dispatch command
  │
  ▼
Autosave    ← service persists
  │
  ▼
Mark Dirty  ← set appropriate dirty flag
```

| Step | What happens | Duration |
|------|-------------|----------|
| **Start** | User initiates action (click, drag, keypress) | Instant |
| **Preview** | Visual feedback during the action (entity follows cursor, polygon preview, marquee) | During interaction |
| **Validate** | Local validation (self-intersection, minimum points, bounds check) | <1ms |
| **Commit** | Command dispatched to mutate document | Sync |
| **Autosave** | Persist document state (debounced) | Async, ~500ms |
| **Mark Dirty** | Set the appropriate dirty flag (geometry/metadata/asset) | Instant |

### Key rule

The compiler is **never** run during this lifecycle. Only the dirty flag is set. Compilation is a separate concern triggered by the compiler service.

## 4. Editing Operations

Every editing action reduces to exactly one of these operations, grouped by domain.

### Geometry operations

| # | Operation | Description | Example | Dirty flag |
|---|-----------|-------------|---------|------------|
| 1 | **Create** | Add new entity to document | Room Tool → Create Polygon | Geometry |
| 2 | **Delete** | Remove entity from document | Select + Delete key | Geometry |
| 3 | **Move** | Change entity position | Drag entity body | Geometry |
| 4 | **Resize** | Change entity dimensions | Drag vertex handle | Geometry |
| 5 | **Split** | Divide polygon at a line | Future tool | Geometry |
| 6 | **Merge** | Combine adjacent polygons | Future tool | Geometry |

### Metadata operations

| # | Operation | Description | Example | Dirty flag |
|---|-----------|-------------|---------|------------|
| 7 | **Rename** | Change label or identifier | Inspector name edit | Metadata |
| 8 | **Assign** | Change category, type, or properties | Inspector category dropdown | Metadata |

### Mapping: Tools → Operations

| Tool | Primary operation | Secondary |
|------|------------------|-----------|
| Select (click entity) | — (selects only) | Delete |
| Select (drag entity) | Move | — |
| Select (drag vertex) | Resize | — |
| Room Tool | Create (polygon) | — |
| Hallway Tool | Create (path) | — |
| Stairs Tool | Create (point) | — |
| Elevator Tool | Create (point) | — |
| Entrance Tool | Create (point) | — |
| Inspector name edit | Rename | — |
| Inspector category | Assign | — |

Every tool implements tool behavior (how the user interacts) and then maps to an operation (what the tool does). New tools never implement ad-hoc mutation logic.

## 5. Selection Engine

**Selection is the primary context of the Interior Editor.** Everything — Inspector, Explorer, Context Header, Tool availability, Validation — reacts to what is selected. The user is not editing tools; they are editing their selection.

### 5.1 State

```
selectedIds: Set<string>    — empty, single, or multiple
lastSelectedId: string|null  — most recently clicked entity
```

### 5.2 Selection modes

| Action | Result |
|--------|--------|
| Click entity (Select tool) | Single select. Replaces previous selection. |
| Click empty space | Clear selection. |
| Shift+Click entity | Toggle in/out of selection set. |
| Ctrl+Click entity | Same as Shift+Click (platform parity). |
| Drag on empty space (Select tool) | Marquee selection — all entities intersecting box are selected. |
| Escape | Three-step: cancel drawing → clear selection → noop |

### 5.3 What selection drives

| Component | Single selection | Multi-selection |
|-----------|-----------------|-----------------|
| Canvas | Entity highlighted (fill + outline) | All selected entities highlighted |
| Explorer (FloorOutliner) | Entity row highlighted | All rows highlighted |
| Inspector | Shows entity properties | Shows count summary ("3 selected") + bulk actions |
| Context Header | — | Shows badge count |
| Keyboard shortcuts | Target for Delete, Copy, Nudge | Target for bulk Delete |
| Validation | Scope for re-validation | — |

### 5.4 Cross-workspace sync

- Explorer selection and Canvas selection share a single source of truth (`SelectionManager`)
- Click entity row in Explorer → select on canvas (no fly-to, no animation)
- Select entity on canvas → highlight in Explorer row
- Explorer auto-expands parent floor if entity not currently visible
- Double-click entity in Explorer: select AND fly-to on canvas

## 6. Tool Model

### 6.1 Tool definitions

| Tool | State entered | Shortcut | Behavior |
|------|--------------|----------|----------|
| Select | Selecting | V / 1 | Click to select. Drag to marquee. Double-click entity to edit vertices. |
| Room | Drawing | R / 2 | Click to place vertices. 3+ points to confirm. |
| Hallway | Drawing | H / 3 | Click to place vertices. 2+ points to confirm. Width control shown. |
| Stairs | Idle (instant) | S / 4 | Single-click to place. Dialog opens for floor range. |
| Elevator | Drawing | E / 5 | Single-click to place. Dialog opens for floor range. |
| Entrance | Idle (instant) | I / 6 | Single-click to place. connectionState = PLACED initially. |

### 6.2 Activation rules

- Activating a different tool: tool switches. Active drawing is cancelled without prompt.
- Activating the same tool: noop (no toggle).
- After confirming a placement: stay in current tool (not auto-return to Select). Administrators typically place multiple items in sequence.

### 6.3 Cursor map

| Context | Cursor |
|---------|--------|
| Select tool, no hover | `default` |
| Select tool, over entity | `pointer` |
| Select tool, over vertex handle | `grab` |
| Select tool, dragging vertex | `grabbing` |
| Select tool, dragging entity | `move` |
| Drawing tools | `crosshair` |
| Panning (Space held) | `grab` → `grabbing` |

## 8. Mouse Model

| Action | Tool | Result |
|--------|------|--------|
| Click | Select | Feature query → select entity or clear |
| Click | Room/Hallway | Add polygon point |
| Click | Stairs/Entrance | Place entity at click position |
| Double-click | Select (on entity) | Enter Vertex Edit mode |
| Double-click | Drawing tool | Confirm polygon |
| Triple-click | Any | No action. Reserved. |
| Drag | Select (on entity body) | Move entity |
| Drag | Select (on vertex handle) | Edit vertex position |
| Drag | Select (on empty space) | Marquee selection |
| Right-click | Any | Cancel drawing. If not drawing, browser context menu. |
| Middle-click / Wheel | Any | Pan / zoom |
| Scroll wheel | Any | Zoom |

### Drag rules

- Drag starts on `mousedown` on entity in Select tool
- During drag, entity visually follows cursor
- On `mouseup`, dispatches Move operation
- If drag distance <5px, treated as click (select, not move)
- Shift+drag constrains to horizontal or vertical axis

### Hover rules

- Hover entity in Select tool: subtle outline highlight, cursor → `pointer`
- Hover vertex handle: cursor → `grab`
- Hover empty: cursor per tool map

## 10. Inspector Behavior

### Open/close

- Opens automatically on single select (or last-selected in multi-select)
- Closes on selection clear
- Width: 240px
- During drawing: Inspector switches to Tool Options for the active tool (e.g. Room Tool shows minimum area, snap, auto-connect, default type). If no tool options defined, preserves last selection state.

### Content by state

| State | Inspector shows |
|-------|----------------|
| Nothing selected | Empty / hidden |
| Single entity | Type-specific properties (name, dimensions, position) |
| Multiple entities | "3 selected" summary + bulk actions (delete, duplicate) |
| Drawing | Tool Options for active tool |

## 11. Dirty State

Four independent dirty flags on the document:

```
geometryDirty: boolean
metadataDirty: boolean
assetDirty: boolean
compilerDirty: boolean
```

| Flag | Set by | Cleared by |
|------|--------|-----------|
| **Geometry Dirty** | Create, Delete, Move, Resize, Split, Merge | Compilation start |
| **Metadata Dirty** | Rename, Assign | Compilation start |
| **Asset Dirty** | Asset operations (panorama replace, QR assign) | Compilation start |
| **Compiler Dirty** | Geometry Dirty (automatically) | Compilation start |

### How they relate

- Geometry Dirty → automatically sets Compiler Dirty (navigation must rebuild)
- Metadata Dirty → does NOT set Compiler Dirty (search index rebuilds independently)
- Asset Dirty → sets Compiler Dirty only if geometry-anchored assets changed

The Editing Engine explicitly declares "the compiler needs attention" rather than making the compiler infer from geometry changes. This keeps Phase 5.5 clean — the compiler reads `compilerDirty` and decides whether to recompile.

## 12. Validation Levels

Three tiers with different scope and cost:

| Level | Scope | When run | Cost | Examples |
|-------|-------|----------|------|---------|
| **Editing Validation** | Current operation only | During Preview, before Commit | Cheap — O(1) or O(n) on current entity | Self-intersection, min points, min area, bounds check |
| **Geometry Validation** | Single floor or entity | After Commit, when geometry dirty | Moderate — O(n) per floor | Polygon closed, overlapping rooms, orphaned entrances |
| **Navigation Validation** | Full navigation graph | During publish or explicit build | Expensive — full graph walk | Connectivity, bridge completeness, anchor integrity |

Editing Validation blocks the commit (user sees feedback before operation completes).
Geometry Validation is a warning (user sees in Problems Panel but can still work).
Navigation Validation is the publish gate (blocks publish if critical errors exist).

Navigation Validation is named after the domain (navigation integrity), not the implementation (compiler). The compiler may change; the validation concept won't.

## 13. Error Prevention

### Guardrails

| Scenario | Response |
|----------|----------|
| Room requires <3 points | Confirm button disabled |
| Hallway requires <2 points | Confirm button disabled |
| Polygon area <1m² | Warning toast, not blocked |
| Self-intersecting polygon | Warning on confirm, visually highlighted |
| Entity outside building footprint | Placement blocked, red circle indicator |

### Safety

- All mutations are undoable (command pattern)
- Delete dispatches command (undoable by default)
- No irreversible operations at the interaction level

## 14. Edge Cases

| Scenario | Resolution |
|----------|-----------|
| Drawing + window resize | State preserved. Confirm bar recenters. |
| Undo during drawing | Removes last point. If no points remain, exit Drawing. |
| Selection + tool switch | Selection cleared. |
| Vertex edit + tool switch | Cancelled. Selection cleared. |
| Entity being dragged + Escape | Drag cancelled. Entity returns to original position. |
| No selection, no drawing | Canvas full-width, navigable. |
| Empty floor | "No rooms yet — select a tool to begin" overlay. |

## 15. Implementation Boundaries

This spec defines:
- The state machine and invariants
- The lifecycle contract
- The geometry operation vocabulary
- The selection engine interface
- The dirty state flags
- The validation tiers and their responsibilities

It does not define:
- The visual design of tool buttons, dock, or context header (Phase 4)
- The data model for entities (already defined)
- The command handlers for mutations (already defined)
- The compiler service's scheduling or execution (Phase 5.5)
- The render loop or MapLibre layer management

## Acceptance Criteria

1. State machine has exactly 6 states with mutual exclusion enforced.
2. Every editing action follows Start → Preview → Validate → Commit → Autosave → Mark Dirty.
3. Every tool maps to exactly one of the 8 geometry operations.
4. Dirty flags are independent — renaming a room sets only metadata dirty.
5. Validation has 3 tiers with different scopes — editing validation blocks commit, geometry validation warns, compiler validation gates publish.
6. Selection is the single source of truth for Inspector, Explorer, Canvas, Context Header, and Tool availability.
7. Escape does a three-step cascade: cancel drawing → clear selection → noop.
8. No tool directly edits compiled navigation artifacts. All editing operations mutate editable document data only (ADR-016).
