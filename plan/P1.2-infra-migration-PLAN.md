## Seam 1 — Persistence: CampusDocument is the source of truth

**Goal**: `save()` serializes `CampusDocument`; load rebuilds it and regenerates
the graph. The compiled graph becomes a pure runtime projection.

> Before each task: re-read `errors/ERRORS.md` (2026-07-15 data-loss + coercion
> entries, 2026-07-08 manifest rule). Preventing: data loss on graph→doc
> inversion; checksum drift on publish.

### T1.1 — Add `CampusDocument` serialization
- **Files**: `packages/core/src/types/document.ts` (or `document-store.ts`); new
  `serialize`/`deserialize` (or `toJSON`/`fromJSON`).
- **What**: cover every entity type — buildings (+footprints, floors, rooms,
  hallways, staircases, elevators, entrances), **roads**, **panoramas**,
  **qrCheckpoints**, and `version`. Fix the gaps `createDocument` currently drops.
- **Acceptance**: unit test — build a populated `CampusDocument` → serialize →
  deserialize → deep-equal on every field. No entity type silently dropped.
- **Checkpoint**: test green.

### T1.2 — `persistenceAdapter.save()` serializes the document
- **Files**: `src/components/studio/EditorBridge.tsx:63-65`, the persistence
  adapter (in `create-editor-context.ts` or `persistence/*`).
- **What**: `save()` writes the serialized `CampusDocument` to localStorage +
  Supabase instead of `graph.toJSON()`. Keep `GraphAdapter.sync` producing the
  runtime graph for the canvas (it stays; its role inverts from "persisted
  model" to "runtime projection").
- **Acceptance**: after Save, stored JSON is a `CampusDocument` shape, not a
  `GraphSnapshot`; canvas still renders (graph regenerated from the doc).
- **Checkpoint**: save→inspect storage shows document JSON; canvas renders.

### T1.3 — Load builds the graph FROM the document
- **Files**: `create-editor-context.ts:82-244` (`createDocument`), `:343-350`
  (`document.changed` → `GraphAdapter.sync`).
- **What**: load path becomes `storedDocument → CampusDocument → GraphAdapter.sync
  → Graph`. `createDocument` may remain as a legacy→doc converter only.
- **Acceptance**: loading a saved document renders the same graph as before.
- **Checkpoint**: reload preserves the edited campus.

### T1.4 — Backward-compatible migration (no data loss)
- **Files**: load path in `EditorBridge.tsx` / `graph-store.ts:206-220`.
- **What**: if stored data is a legacy `Graph` (no `CampusDocument` marker),
  convert once via existing `createDocument` and re-save as a document. Guard
  against overwriting a good graph with a lossy doc.
- **Acceptance**: an existing legacy-graph campus still loads and can be
  re-saved as a document without losing buildings/roads present in the graph.
- **Checkpoint**: e2e — load legacy campus, save, reload; buildings + roads
  survive; 0 console errors.

### T1.5 — Storage schema for the document
- **Files**: `src/app/api/graph/route.ts:50-65`, `sync_graph_snapshot` SQL
  (`migrations/001_initial_schema.sql:134-161`).
- **What**: store document-shaped JSONB as the source of truth; normalized
  `buildings`/`route_nodes`/`route_edges` may remain derived. Do NOT persist the
  compiled graph as the source.
- **Acceptance**: save persists document; publish still writes build artifacts
  to `demo-output/` (runtime bundle — allowed).
- **Seam 1 VERIFY gate**: full save→reload round-trip preserves all entity types;
  `Entity not found` never appears; 0 console errors; checksums valid if publish
  touched.

## Seam 2 — InteractionController → pure event router

**Prereq**: Seam 1 done (graph is a runtime projection; document is source).

> Before each task: re-read `errors/ERRORS.md` (2026-07-15 `Entity not found`,
> 2026-07-15 canvas road leak). Preventing: breaking canvas interactions that
> have no tool replacement (G1–G9).

### T2.1 — Resolve the InteractionController gaps (G1–G9)
- **G1 node delete**: add to `selectTool` — when a graph node is resolved via
  `resolveGraphNodeSelection`, delete resolves to the source entity through an
  `entity.delete` command (graph node has no SelectionManager repr).
- **G2 node highlight**: drive highlight from `SelectionManager` selection in
  `NavigationGraphRenderer`; remove `map.setFeatureState`.
- **G3 legacy bridges**: removed in Seam 3 (do not delete here; `selectTool`
  still needs them until T3.1).
- **G4 drawing preview**: move preview rendering into the draw tools (or a
  shared helper) so `InteractionController` stops owning it.
- **G5 room drag-rectangle**: implement in `draw-room-tool`, or formally accept
  click-vertices as canonical (scope decision — get sign-off).
- **G6 / G7 asset + boundary**: confirm dead (not in toolbar) and scope out.
- **G9 vertex editing**: wrap `useVertexEditor` as a registered tool, or keep it
  orthogonal but strip all graph mutation from `InteractionController`.
- **Acceptance**: every behavior in `InteractionController.tsx` is either covered
  by a tool, scoped out with sign-off, or explicitly retained as router-only.
- **Checkpoint**: gap matrix closed; no uncovered behavior remains.

### T2.2 — Strip InteractionController to a router
- **Files**: `src/components/studio/InteractionController.tsx` (492 lines).
- **What**: keep only `map.on(click/mousedown/mousemove/mouseup/dblclick)` →
  determine active `ToolRegistry` tool → delegate `tool.onPointerDown/Move/Up/
  KeyDown`. Delete legacy branches (`:202-243`), `removeNode` (`:431`),
  `updateBuilding`/`addComponentWithPolygon` (`:383,400`), `setFeatureState`
  (`:419-420`), the `legacySelect*` bridges (`:41-47`).
- **Acceptance**: all canvas interactions still work via tools; grep confirms no
  `useGraphStore` authoring / `legacySelect` in `InteractionController`.
- **Seam 2 VERIFY gate**: full canvas smoke test (select, draw room/road/building,
  move, delete, vertex edit, highlight) passes; 0 console errors.
