# M2.1 — UI Integration Layer Plan

## Dependency Chain

```
T1 (EntityId types)                     ← no dependencies
    ↓
T2 (SelectionManager extension)          ← depends on T1
    ↓
T3 (ExplorerAdapter)                     ← depends on T1 (uses EntityId)
    ↓
T4 (SelectionStore)                      ← depends on T1, T2
    ↓
T5 (SelectionBridge)                     ← depends on T2, T4
    ↓
T6 (WorkspaceContext)                    ← depends on T4
    ↓
T7 (Verify all 430+ tests pass)         ← depends on T1–T6
```

---

## T1 — EntityId Branded Types and Selection Types

**Description:** Replace raw `string` for entity IDs with a branded `EntityId` type. Define `SelectionOrigin` enum, `SelectionMode` type, `EntitySelector` discriminated union, and the enhanced `SelectionState` interface.

**Files to create/touch:**
- `packages/editor/src/context/entity-id.ts` (NEW) — brand type, EntityId, EntitySelector, SelectionOrigin, SelectionMode, SelectionState
- `packages/editor/src/context/index.ts` — re-export

**Acceptance:**
- `EntityId` is a branded string (`Brand<"EntityId">`)
- `SelectionOrigin` is an enum with `Canvas | Explorer | Inspector | Keyboard`
- `SelectionMode` is `"single" | "multi" | "marquee"`
- `EntitySelector` is a discriminated union: `{ type: "building", id: EntityId } | { type: "floor", id: EntityId, buildingId: EntityId } | ...`
- `SelectionState` includes `selected: EntitySelector[]`, `hovered: EntitySelector | null`, `mode: SelectionMode`, `origin: SelectionOrigin`

---

## T2 — Extend SelectionManager

**Description:** Add `selectionMode`, `selectionOrigin`, marquee tracking, `hoveredEntitySelector`, and `activeSelection` to the existing `SelectionManager` service. Add listener support (besides EventBus emit) for the SelectionStore to consume.

**Files to touch:**
- `packages/editor/src/selection.ts`
- `packages/editor/src/context/service-registry.ts` — ensure ServiceMap stays in sync
- `packages/editor/src/eventbus.ts` — verify selection.changed payload is updated

**Acceptance:**
- `select(id, origin?)` accepts optional origin parameter
- `setMode(mode: SelectionMode)` switches selection behavior
- `getSelection(): SelectionState` returns full enriched state
- Multiple rapid selections emit debounced events
- Backward compatible: existing callers still work with just `select(id)`

---

## T3 — ExplorerAdapter

**Description:** Pure function that projects `CampusDocument` into a typed tree of `ExplorerNode[]`. No React, no state, just transformation.

**Files to create/touch:**
- `packages/editor/src/explorer/adapter.ts` (NEW) — ExplorerNode types + adapter function
- `packages/editor/src/explorer/index.ts` (NEW) — re-export

**Types:**
```typescript
interface ExplorerNode {
  id: EntityId
  label: string
  type: 'campus' | 'building' | 'floor' | 'room' | 'hallway' | 'staircase' | 'elevator' | 'entrance'
  children?: ExplorerNode[]
  metadata?: Record<string, unknown>
  entitySelector: EntitySelector
}
```

**Acceptance:**
- `toExplorerNodes(document)` returns a flat or nested tree of ExplorerNodes
- Each node carries an `entitySelector` that uniquely identifies the entity
- The adapter is a pure function with no side effects
- Unit tests for each entity type projection

---

## T4 — SelectionStore

**Description:** React-side store/hook that subscribes to `SelectionManager`'s `selection.changed` events and provides reactive state to components. Components use `useSelection()` instead of subscribing to the service directly.

**Files to create/touch:**
- `packages/editor/src/context/selection-store.ts` (NEW)
- `packages/editor/src/context/index.ts` — re-export

**Acceptance:**
- `useSelection()` returns `{ selected, hovered, mode, origin, select, toggle, clear, setMode, setHover, clearHover }`
- Subscription uses `useSyncExternalStore` or equivalent for React 18/19 compatibility
- Re-renders are batched (no cascade on rapid selection changes)
- Works outside React (testable standalone)

---

## T5 — SelectionBridge

**Description:** Synchronizes legacy Zustand stores (`useStudioStore`, `useGraphStore`) through `SelectionManager`. Prevents update loops by tracking origin.

**Files to create/touch:**
- `packages/editor/src/context/selection-bridge.ts` (NEW)
- `packages/editor/src/context/index.ts` — re-export

**Acceptance:**
- Legacy `selectedNodeId` / `selectedTraceId` in Zustand updates when SelectionManager changes
- SelectionManager updates when legacy stores change (through bridge)
- Origin tracking prevents infinite sync loops
- Bridge is opt-in (wired in EditorProvider, not forced)

---

## T6 — WorkspaceContext

**Description:** Derives active workspace context from selection state. Answers: "what is the user working on right now?" No new state — pure derivation.

**Files to create/touch:**
- `packages/editor/src/context/workspace-context.ts` (NEW)
- `packages/editor/src/context/index.ts` — re-export

**Acceptance:**
- `useWorkspace()` returns `{ mode: 'campus' | 'building' | 'floor' | 'validation' | 'none', activeBuildingId?: EntityId, activeFloorId?: EntityId }`
- Campus mode when nothing selected
- Building mode when a building is selected
- Floor mode when a floor entity is selected
- Can derive from selection without synchronously re-rendering

## Error Prevention

| Task | Potential Error | Prevention |
|------|----------------|------------|
| T1 | Branded type breaks existing code | Use `EntityId` as alias first, migrate callers incrementally |
| T2 | SelectionManager gets bloated | Don't add state — only add metadata (mode, origin) |
| T4 | React re-render storms from rapid selection | Use `useSyncExternalStore` with shallow comparison |
| T5 | Infinite sync loop between bridge and manager | Track `origin` — skip bridge writes if origin is from the bridge itself |
| T6 | WorkspaceContext becomes stale | Derive, don't store — always compute from current selection |
