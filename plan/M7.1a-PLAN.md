# M7.1a — Journey Model Plan

Based on `spec/M7.1a-JOURNEY-MODEL.md`. This milestone defines the workflow vocabulary
for all composition services — pure types only, no orchestration logic.

## Architecture Invariants (from spec)

- **JourneyStep is immutable.** Steps are readonly snapshot DTOs. After construction they are
  never mutated; journey progression occurs by advancing the current step index, not by
  modifying existing steps.
- **JourneyStep contains only data.** No methods, callbacks, promise resolvers, or UI types.
- **Journey owns progression.** `next()`, `previous()`, `respond()`, `reset()` are dispatched
  on Journey, not distributed across steps.
- **`currentStepId` MUST always equal `current().id`.** These are not independent state
  variables — `currentStepId` is derived from the step at `currentIndex`.
- **`respond()` dispatches by step kind.** The response type is determined by the active
  interaction step (`SelectDestinationStep` → `string`, `SelectEntranceStep` → `string`,
  `ConfirmStep` → `boolean`). Type validation lives inside `Journey.respond()`, not in the
  application.
- **No pipeline/artifact/viewer types** appear in any step variant. Verified by the existing
  layer-boundary gate.

### T1 — Domain model types

**Files to touch:**
- `packages/runtime/src/composition/journey-model.ts` (create)

**What:**
Define the type system with zero behavior:

```ts
type JourneyStatus = 'not-started' | 'in-progress' | 'waiting-on-user' | 'complete' | 'failed'

interface JourneyStepBase {
  readonly id: string
  readonly kind: string
}

// Automatic steps
interface LocateStep extends JourneyStepBase { readonly kind: 'locate'; readonly location: LocationContext }
interface SearchStep extends JourneyStepBase { readonly kind: 'search'; readonly results: SearchResult[] }
interface NavigateStep extends JourneyStepBase { readonly kind: 'navigate'; readonly route: Route; readonly destination: BuildingResult; readonly entrance: EntranceResult }
interface ArrivalStep extends JourneyStepBase { readonly kind: 'arrive'; readonly building: BuildingResult; readonly floor: number }
interface PanoramaStep extends JourneyStepBase { readonly kind: 'panorama'; readonly panorama: PanoramaResult }

// Interactive steps
interface SelectDestinationStep extends JourneyStepBase { readonly kind: 'select-destination'; readonly query: string; readonly candidates: SearchResult[] }
interface SelectEntranceStep extends JourneyStepBase { readonly kind: 'select-entrance'; readonly building: BuildingResult; readonly entrances: EntranceResult[] }
interface ConfirmStep extends JourneyStepBase { readonly kind: 'confirm'; readonly prompt: string; readonly options: ConfirmOption[] }
interface ConfirmOption { readonly id: string; readonly label: string }

type JourneyStep = LocateStep | SearchStep | NavigateStep | ArrivalStep | PanoramaStep
  | SelectDestinationStep | SelectEntranceStep | ConfirmStep
```

**Dependencies:** All DTO types (`LocationContext`, `SearchResult`, `BuildingResult`,
`EntranceResult`, `Route`, `PanoramaResult`) imported from `../../engine` (the M6 barrel).
`LatLng` from `@navi/core`.

**Acceptance:** Pure type definitions compile. No runtime imports. No RuntimeEngine dependency.

### T2 — Journey class

**Files to touch:**
- `packages/runtime/src/composition/journey-model.ts` (extend)

**What:**
Add the `Journey` class:

```ts
class Journey {
  readonly id: string
  readonly request: string
  readonly position: LatLng
  private _steps: JourneyStep[]
  private _index: number
  private _status: JourneyStatus

  get steps(): readonly JourneyStep[]
  get currentIndex(): number
  get currentStepId(): string  // always equals current().id
  get status(): JourneyStatus

  current(): JourneyStep
  next(): JourneyStep           // advances index, returns step
  previous(): JourneyStep       // retreats index, returns step
  respond(response: unknown): void  // validates against current step kind, sets status
  reset(): void                 // index = 0, status = 'not-started'
  isComplete(): boolean         // status === 'complete'
}
```

**Status transitions:**
- Constructor: `not-started`, index 0
- `next()` while `not-started` → `in-progress`
- `next()` on last step → `complete`
- Interaction step reached → `waiting-on-user`
- `respond()` called → back to `in-progress`, advances to next auto step
- `reset()` → `not-started`, index 0

**Edge cases:**
- `previous()` at index 0: stays at 0, doesn't throw
- `next()` while `waiting-on-user`: throws (must respond first)
- `respond()` while not `waiting-on-user`: throws
- `respond()` with wrong type for current step: throws
- `next()` when `complete`: returns last step, doesn't throw

**Acceptance:** Journey class compiles, all edge cases handled.
