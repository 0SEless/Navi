# M3.2.2 Phase 3 — Context Header

## What

Replace the current ad-hoc header bar in FloorEditor (`FloorEditor.tsx` lines 83–110) with a dedicated ContextHeader component that establishes identity and orientation inside the Interior Editor.

The current header is a mixed bag of breadcrumb, floor label, sync status, and "FLOOR EDITOR" branding — all inline in the parent component. Phase 3 extracts it into its own component, aligns it with the interaction model (Phase 4.5), and adds selection awareness.

## Mockup

```

                   Engineering Building / Ground Floor                         ● Saved
```

Left: back button. Center: current location (building / floor). Right: autosave status, selection count.

## Acceptance Criteria

1. ContextHeader is a standalone component in `packages/editor/src/panels/` with no direct dependency on FloorEditor internals.
2. Shows building name and floor label (e.g. "Engineering Building / Ground Floor").
3. Back link navigates to Campus Workspace (`/studio/{mapId}/edit`).
4. Autosave status indicator shows one of: Saved (green dot), Saving (amber), Unsaved (grey), Error (red).
5. When multi-selection is active (selectedIds.size > 1), shows "N selected" badge.
6. No regressions in existing tests. New tests for ContextHeader component.

## Non-goals

- No toolbar functionality (Phase 4).
- No interaction state display (the header is read-only view of location + status).
- No redesign of the back link behavior (uses existing Next.js Link).
- No changes to autosave service itself — only its display.
