# M3.2.2 Phase 4 — Tool Dock

## What

Replace the current inline tool list (FloorEditor.tsx lines 140–156) with a floating ToolDock component that is workspace-aware, groups tools by category, and never bounces back to Select after use.

## Design

### Layout

Floating bar centered below canvas top, with visual separators between groups:

```
🖱 ✋ │ ▭ ═ │ 🚪 🪜 🛗
```

### Groups

| Group | Campus tools | Interior tools |
|-------|-------------|----------------|
| Navigation | Select, Pan | Select, Pan |
| Geometry | Building, Road, Boundary | Space, Hallway |
| Connections | — | Entrance, Stair, Elevator |

### Behavior

- **Stay in tool:** After confirm/placement, stay in current tool. No auto-return to Select.
- **Spacebar:** Temporary pan. Hold Space → grab cursor. Release → back to previous tool.
- **Escape:** Cancel drawing → activate Select tool → clear selection (hierarchical).
- **Active state:** Raised button with subtle shadow and accent border (not just color).

### Keyboard shortcuts

| Key | Tool |
|-----|------|
| `V` | Select |
| `H` | Pan (Hand) |
| `R` | Space (Room) |
| `T` | Hallway |
| `E` | Entrance |
| `S` | Stair |
| `I` | Elevator |

### Tool labels on hover

Each tool button shows its keyboard shortcut on hover (e.g. "Space (R)").

### Workspace awareness

Same dock component. Different tool sets per workspace. The dock receives tool definitions from the workspace — it never hardcodes tool IDs.

### Architecture

```
Workspace → Tool groups (grouped tool configs) → ToolDock → renders buttons
```

The ToolDock knows about **groups** (it renders separators between them) but not about individual tool IDs. Tool definitions flow in as data.

### Non-goals

- Panorama tool — removed from dock. Panoramas are assets managed in the Inspector.
- Utilities (Measure, Guide, Snap) — future, not MVP.
- Floor selector, Publish, Validate, Save, QR — not in dock.
- Context menu — future (Phase 4.5).

## Acceptance Criteria

1. ToolDock renders as a floating bar with group separators.
2. Active tool has distinct visual state (raised, shadow, accent border).
3. Hovering a tool shows its keyboard shortcut.
4. Tool stays active after use (no auto-return to Select).
5. Tool sets differ per workspace (campus vs interior).
6. No hardcoded tool IDs in the ToolDock component.
7. All existing tests pass. New tests for ToolDock.
