# M6.5a — Panorama Package Extension

## What

Extend the published navigation package with a new **optional** `panoramaIndex` artifact so that panorama data (currently only living in the Studio document and as POI graph nodes) becomes first-class runtime data. This is the prerequisite for `PanoramaService` (M6.5b), which will follow the same capability pattern as Navigation/Search/Buildings/Location.

This milestone spans the pipeline (compiler → package format → publisher → loader) by **adding** a new optional artifact. It does not change any existing artifact contract, so it is forward-compatible and does not reopen the frozen pipeline layers (ADR-009/010/011/012 explicitly permit new optional artifacts/fields).

### Why this exists

Every existing runtime capability is backed by a published artifact:

| Runtime Capability | Published Artifact    |
| ------------------ | --------------------- |
| NavigationService  | Graph                 |
| SearchService      | SearchIndex           |
| BuildingService    | BuildingIndex         |
| LocationService    | Graph + BuildingIndex |
| PanoramaService    | ❌ Missing             |

Panorama is the first capability whose domain model never leaves Studio. That is a packaging gap, not a runtime problem. M6.5a closes it.

### Public (application-facing)

No runtime API yet. This milestone only changes what the package *contains*.

```
Studio Document (panoramas)
      │
Compiler (emits panoramaIndex)
      │
Navigation Package (panorama.json)
      │
Publisher (writes artifact)
      │
Loader (hydrates panoramaIndex)
      │
LoadedPackage.panoramaIndex?
```

### Invariants

- **`panoramaIndex` is optional everywhere.** Existing packages without it remain valid; older runtimes ignore it; new runtimes consume it when present.
- **No existing artifact changes.** `graph`, `searchIndex`, `buildingIndex`, `poiIndex`, `spatialIndex` and their file/type shapes are untouched.
- **Panorama data is a faithful, read-only projection of `document.panoramas`.** The compiler does not invent or enrich panorama fields; it passes through the document's panorama model.
- **Hotspots are preserved.** Each panorama carries its `hotspots` array (target type/id, yaw, pitch, label) into the package.
- **Viewer-agnostic.** The package carries panorama *data* only — no Pannellum/scene/camera concepts leak into the format.
- **Deterministic.** Given the same `document.panoramas`, the emitted `panoramaIndex` is byte-identical (sorted by id).

## Success Criteria

1. `core` defines `PanoramaIndex` (runtime) and `PanoramaIndexFile` (package format) types, each with `panoramas: PanoramaEntry[]` / `PanoramaEntryFile[]` and `version`.
2. `PanoramaEntry` carries: `id`, `title` (label), `imageAssetId`, `buildingId?`, `floor?`, `position: LatLng`, `heading?`, and `hotspots: HotspotEntry[]`.
3. `HotspotEntry` carries: `id`, `type` ('navigation' | 'information' | 'link'), `target` (id), `yaw`, `pitch`, `label`.
4. `NavigationArtifacts` gains optional `panoramaIndex?: PanoramaIndex`.
5. Compiler `buildArtifacts` emits `panoramaIndex` from `document.panoramas` (pass-through, sorted by id).
6. Package format `NavigationPackageManifest.artifacts` may include a `panorama` entry; publisher writes `panorama.json`.
7. `LoadedPackage` gains optional `panoramaIndex?: PanoramaIndex`; loader hydrates it.
8. All existing tests pass; packages without a panorama artifact load unchanged.

## Non-goals

- No `PanoramaService` runtime API (that is M6.5b).
- No changes to graph/POI representation of panoramas (the POI node for panorama anchors remains).
- No viewer/scene concepts in the package format.
- No schema version bump of existing artifacts.

## Acceptance Criteria

- A document with N panoramas compiles to a `panoramaIndex` with N entries, ids preserved, hotspots preserved.
- A package published with `panoramaIndex` is loadable; `loaded.panoramaIndex` is defined and matches the source panoramas.
- A package published without panoramas (or an older package) loads with `panoramaIndex === undefined` and no error.
- Round-trip verification (publisher verifier) passes with the new artifact present.
- Compiler output is deterministic for identical input documents.

## API (types added)

```ts
// @navi/core — runtime artifact
interface HotspotEntry {
  readonly id: string
  readonly type: 'navigation' | 'information' | 'link'
  readonly target: string
  readonly yaw: number
  readonly pitch: number
  readonly label: string
}

interface PanoramaEntry {
  readonly id: string
  readonly title: string
  readonly imageAssetId: string
  readonly buildingId?: string
  readonly floor?: number
  readonly position: LatLng
  readonly heading?: number
  readonly hotspots: readonly HotspotEntry[]
}

interface PanoramaIndex {
  readonly version: string
  readonly panoramas: readonly PanoramaEntry[]
}

// @navi/core — package file
interface HotspotFile {
  id: string
  type: 'navigation' | 'information' | 'link'
  target: string
  yaw: number
  pitch: number
  label: string
}

interface PanoramaEntryFile {
  id: string
  title: string
  imageAssetId: string
  buildingId?: string
  floor?: number
  lat: number
  lng: number
  heading?: number
  hotspots: HotspotFile[]
}

interface PanoramaIndexFile {
  schemaVersion: string
  panoramas: PanoramaEntryFile[]
}
```

## Technical Considerations

- `PanoramaEntry.title` maps from document `Panorama.label`; `heading` from `Panorama.heading`. The document model is the source of truth.
- Hotspot `type` is normalized: document `PanoramaHotspot.target.type` of `'panorama' | 'room' | 'entrance' | 'qr'` → `'navigation'`; `'url'` → `'link'`; informational hotspots (no target) → `'information'`. (M6.5a preserves raw target semantics conservatively; see Known Pitfalls.)
- Sorting by id guarantees deterministic output for checksum stability.
- The loader treats `panorama` like `poi`/`building`: optional, validated, converted, and attached to `LoadedPackage` only when present.
- Follows ADR-010/012 extension rules: new optional artifact, no existing contract modified.

## Known Pitfalls

- Don't make `panoramaIndex` required — that would break every existing package and violate the freeze.
- Don't alter the document `Panorama` model here; M6.5a only projects it.
- Hotspot target typing: the document distinguishes target types (`panorama`/`room`/`entrance`/`qr`/`url`). M6.5a keeps `target` as the raw id and a coarse `type` ('navigation' | 'information' | 'link'); fine-grained target-type routing is a consumer concern (M6.5b / viewer).
- Publisher `ARTIFACT_NAMES` and `schemaVersions` must include `panorama` or the artifact is silently skipped.
- Loader registry + converter + validator must all be added together or the artifact is reported SKIPPED.
