# Shared stair and door representations

Owner approved implementation of the proposed next release: raised stairs/landings, framed door panels with solid/glass choices, and consistent Studio/public rendering. This document records the concrete implementation choices; no further saved-map change or commit is authorized.

- Build procedural geometry with the existing MapLibre extrusion pipeline and shared core local-meter helpers. No new 3D engine or downloaded models.
- Stairs follow authored resolved footprint, rotation, direction, step count and existing preset. Retain real landings and the local floor-to-floor rise where available. Do not replace authored turning stairs with an unrelated straight flight. Position-only stairs retain a marker and a diagnostic instead of inventing dimensions. Generated geometry is decorative and cannot modify stair links or routing.
- Door frames fit actual apertures; a thin solid or glass panel sits slightly ajar (30 degrees, visual convention). Add optional doorAppearance open/solid/glass to door records and canonical door openings; absent values render solid without materializing saved defaults. Open means frame without panel. Dimensions and wall attachments remain authoritative; door appearance never changes routing/accessibility. Unresolved attachment/geometry is reported, never guessed onto another wall.
- Appearance styles selectable in the floor inspector. Applying unchanged appearance is a no-op; strict forward enum validation and exact inverse snapshots preserve imported legacy states. Old snapshots remain loadable without migration.
- Propagate door appearance and stair drawing/landing/rise data through compiler, runtime conversion/service, parts and public render model. Share geometry functions between Studio and public layers. Public architecture is scoped to the selected building/active floor and pitched view; keep legacy 2D rendering and source-less fallbacks. Active-floor datum is zero; do not create stacked-building/terrain elevation behavior in this task.
- Render true wall apertures, door frames/panels/glass, stairs and existing window assets consistently in the new canonical public architecture layer; avoid duplicate old opaque wall/door layers in that mode. Retain usable fallback symbols for incomplete legacy geometry.
- No saved-map writes, Save/Done/Publish, force-release, commits or staging. Test only the authorized map-map-1-375k/bldg-2-emz6/floor0 in a disposable browser draft, and a synthetic public artifact fixture through the actual public rendering component; no publishing fixture or protected ASU changes.
- Verification: serial 512MB focused tests, producer/consumer checks, malformed/missing/rotated geometry and finite positive solids, public building/floor/camera gates, meaningful browser screenshots/zero page errors, exact saved-checksum comparison and own-lock release. No full build or second dev server. Preserve previous feature checkpoints; create a new guarded checkpoint before changes.

Preventing: meter/degree confusion, lost compiler whitelist fields, fake stair rise from rotation, opaque glass, stale MapLibre style readiness, duplicated assets, unrelated building leakage, invented geometry for missing data, undo/schema regressions and unsafe saved-map changes.
