# P1.2 — Complete the Infrastructure Migration

## WHAT

Remove the last three legacy seams at the compiler/persistence boundary so that
**every interaction enters the new architecture exactly once**. This is a
migration milestone, not a feature: it makes `CampusDocument` the single source
of truth and deletes the parallel legacy interaction/selection paths.

Three seams, in dependency order (each depends on the one before):

1. **Seam 1 — Persistence**: persist `CampusDocument`; regenerate the Navigation
   Graph from it. Today the legacy `Graph` JSON is the stored model and
   `CampusDocument` is built *from* it on load (inverted).
2. **Seam 2 — InteractionController**: reduce it to a pure event router that
   delegates pointer events to the active `ToolRegistry` tool. Delete all
   authoring / selection / graph-mutation / deletion / highlight logic from it.
3. **Seam 3 — Canvas node selection**: route canvas graph-node clicks through
   `resolveGraphNodeSelection` → `SelectionManager` (or highlight-only). Delete
   `legacySelectNode` / `legacySelectTrace` from the new architecture.

ADR 005 ("graph is derived, selection is entity-centric") is only half-true
until Seam 3 lands; ADR 006 (this milestone) makes "derived graph is never the
stored model" a permanent rule.

## Success criteria

1. **S1 — Source of truth inverted.** `persistenceAdapter.save()` serializes
   `CampusDocument`; load reconstructs `CampusDocument` and regenerates the
   Navigation Graph. The compiled graph is never persisted as the stored model.
2. **S2 — `CampusDocument` round-trips losslessly.** A `serialize`/`deserialize`
   pair exists and is tested for every entity type, including `roads`,
   `panoramas`, `qrCheckpoints`, and `version`.
3. **S3 — No data loss on migration.** Existing campuses stored as legacy graphs
   still load (one-time conversion) with roads/panoramas/QR preserved where the
   stored graph contains them.
4. **S4 — InteractionController is a router only.** All canvas interactions are
   handled by `ToolRegistry` tools; no graph mutation, legacy selection, node
   deletion, or `setFeatureState` highlight remains in `InteractionController`.
5. **S5 — Canvas graph-node click is entity-centric.** Clicking a graph node
   selects its source entity (via provenance) or highlights only; `legacySelectNode`
   / `legacySelectTrace` are gone from the new path.
6. **S6 — Behavior parity.** Node delete, node highlight, drawing preview, room
   creation, and vertex editing still work (via tools or explicitly scoped out
   with sign-off). 0 console errors; no `Entity not found: N00xx`.

## Known gaps that block a naive deletion (must be resolved in Seam 2)

From the InteractionController coverage audit:

- **G1** Node deletion (Delete → `useGraphStore.removeNode`) has no tool. Graph
  nodes are derived; deletion must resolve to the source entity and run an
  entity-delete command, or be scoped out.
- **G2** Selected-node highlight via `map.setFeatureState` has no tool. Replace
  with `SelectionManager`-driven highlight in `NavigationGraphRenderer`.
- **G3** `legacySelectNode` / `legacySelectTrace` bridges are still *required* by
  `selectTool` (the Seam 3 blocker). Removed only after Seam 3.
- **G4** Drawing preview rendering lives in `InteractionController` (tools
  accumulate vertices but render nothing). Move preview into the draw tools or a
  shared render helper.
- **G5** Room drag-rectangle UX (`addComponentWithPolygon`) has no replacement
  (`draw-room` uses click-vertices). Build it or accept click-vertices as
  canonical (scope decision).
- **G6 / G7** `asset` click-placement and `boundary` drawing are not in the
  toolbar and appear dead — confirm and scope out.
- **G9** Vertex editing lives in `useVertexEditor` (separate map listeners), not
  a registered tool. Wrap as a tool or keep orthogonal but remove graph mutation
  from `InteractionController`.

## Pitfalls (from errors/ERRORS.md)

- **Data-loss on inversion** (2026-07-15 graph-node entries, 2026-07-08 manifest
  rule): `createDocument` currently drops `roads`/`panoramas`/`qrCheckpoints` and
  never sets `version`; stored graphs may already lack them. Any save that writes
  a `CampusDocument` reconstructed from such a graph will permanently lose those
  entities. Mitigation: add real serialization first (T1.1), keep backward-compat
  read (T1.4), and never overwrite a legacy graph with a lossy document until
  conversion is verified.
- **Checksum/size mismatch** (2026-07-08): publish artifacts must compute
  checksums from the exact bytes written. Applies if Seam 1 touches publish.
- **Selection coercion** (2026-07-15 `Entity not found`): never bridge a derived
  id into `SelectionManager`; always resolve via `componentId` provenance.
